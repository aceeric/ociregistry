# Version 2.3.0

This version adds a background watcher for new images to load, and a supporting ledger so that both preload and watch only process a file once.

## Watching for new images

Watch is an extension of preload. So to enable it you must also enable preload. E.g.:

```sh
ociregistry serve --preload /mnt/somedir --watch-frequency 1m
```

With a watch frequency (`watchFrequency: 30s` in the config file, or `serve --watch-frequency 30s`), the server keeps checking its preload images while it runs, and loads new or changed image tarballs and image list files into the running cache. Images can be added by copying files into the preload location, with no restart. This mainly supports air-gapped environments and upstream outages.

- The watcher watches exactly what `preloadImages` resolves to, so it needs `preloadImages` set. The server access this location read-only, so it can be mounted read-only.
- A new file is loaded once it's unchanged between two checks. The server ignores `.part` files. So - copy files in as `name.part` and rename them when the copy is complete. On NFS (including AWS EFS) this is required.
- Image list files need the upstream: when the server is air-gapped each one is logged as an error. Tarballs always load.
- The frequency must be at least `5s`.

See [Watching For New Images](../docs/docs/watching.md).

## The preload ledger

The server now records each file it preloads (and each file the watcher loads) in `metadata/loaded.yaml` in the image cache, and doesn't process a file again unless it changes. As a result:

- **Restarts are faster:** archives that were already loaded aren't read again.
- **Pruned images stay pruned:** before, a restart re-read every preload file and restored images a prune had removed. Now an image that ages out of the cache stays out.
- **A failed file doesn't stop the server:** a preload file that fails is logged as an error and recorded as failed, and the server starts with the rest. It isn't retried until it changes.
- **No matches is not an error:** a preload path that matches no files - like an empty directory or a glob - is logged at info level, since files may be added later. A path that doesn't exist (with no glob characters) is still an error.

The first start after upgrading has no ledger, so every preload file is processed once, as before, and recorded.

To process files again, stop the server, edit or delete `metadata/loaded.yaml`, and re-start. The `load` sub-command doesn't use the ledger: it always loads what it's given, so `ociregistry load --images ...` reloads everything, including pruned images.

## Loaded images have no pull date

An image loaded by the watcher from an image list file used to get a pull date as if a client had pulled it. Now nothing that's preloaded or loaded gets a pull date until a client pulls it, as was already the case for tarballs. Pruning by pull date (`type: accessed`) therefore only removes images that clients have pulled.

## The `load` sub-command tries every file

The `load` sub-command used to stop at the first file that failed. Now it tries every file, logs each one that fails, and loads the rest. Its exit codes:

| Exit code | Meaning |
|-|-|
| `0` | Every file loaded, or was already cached. A glob that matches nothing, or an empty directory, is `0` too. |
| `1` | The path couldn't be resolved, so nothing was loaded: a path that doesn't exist (with no glob characters), a directory that can't be read, or a malformed glob. |
| `3` | Some files failed: they're logged, and the rest were loaded. |

Scripts that treated any non-zero exit as "nothing loaded" should check for `3`.

## Preload and load paths

- `--preload-images` and `load --images` accept a directory: its files, one level deep.
- Files whose names end in `.part` are skipped, symlinks are followed (so a mounted ConfigMap or Secret works), and a file named more than once is loaded once.
- If `--preload-images` is given a non-existent or un-reachable path (i.e. permissions error), the server will not start

## `load --images`

The `load` command's `--image-file` arg is renamed `--images` (config key `images`). The old `--image-file` (config key `imageFile`) still works but it's deprecated and will be removed in a future release. If both are specified it's not an error: `--images` wins.
